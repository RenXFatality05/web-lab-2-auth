# Лабораторна робота №2

Реєстрація та авторизація за допомогою JWT. Варіант 5.

## Запуск

Потрібен Node.js 24 або новіший. У терміналі з папки «Лаб 2» виконай:

```powershell
npm ci
npm run create-admin -- admin
npm start
```

Команда створення адміністратора потрібна один раз. Вона виведе згенерований пароль у термінал. Відкрий [http://127.0.0.1:3001](http://127.0.0.1:3001).

Щоб підставити свої дані в JWT, скопіюй `student.example.json` у `student.json` і заповни його. Без локального файлу застосунок використовує дані з шаблону.

## Перевірка

1. Зареєструй новий логін, наприклад `student5`, і увійди під ним. У профілі має бути роль `user`.
2. Вийди й увійди під логіном `admin` зі згенерованим паролем. Натисни «Переглянути користувачів». У таблиці буде видно обидва облікові записи та їхні ролі.
3. Після входу зачекай 65 секунд. Застосунок поверне тебе до форми входу та покаже повідомлення про закінчення дії токена.
4. Щоб побачити передачу JWT, відкрий інструменти розробника браузера. На вкладці Network вибери запит `GET /api/profile` після входу. У заголовках запиту буде `Authorization: Bearer …`.

## Як це працює

- `POST /api/register` створює обліковий запис із роллю `user`. Пароль зберігається у вигляді хешу scrypt з індивідуальною сіллю в локальній базі SQLite.
- `POST /api/login` перевіряє пароль і видає підписаний JWT. У payload є ідентифікатор і роль користувача, прізвище та ініціали студента, група, номер варіанта й час завершення дії. Для варіанта 5 термін дії становить 60 + 5 = 65 секунд.
- `GET /api/profile` перевіряє підпис і термін дії токена. За відсутності дійсного токена сервер повертає 401.
- `GET /api/admin/users` додатково перевіряє роль у базі. Звичайному користувачу сервер повертає 403. Адміністратор отримує список логінів і ролей.
- Токен зберігається в пам’яті вкладки. Після оновлення сторінки або перезапуску сервера потрібно увійти знову. Облікові записи зберігаються в `data/users.sqlite`.
